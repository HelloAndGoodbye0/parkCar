### 1.2 新增中间件

| 中间件 | 版本建议 | 用途 | 是否必须（首期） |
| ---- | ---- | ---- | ---- |
| Redis | 7.x | 车位状态缓存、开闸指令防重、分布式锁、小程序会话 | 必须 |
| RabbitMQ | 3.13 | 设备识别事件异步处理、支付回调解耦、通知推送 | 建议 |
| MinIO | 2024 版 | 抓拍图片、发票文件存储 | 建议 |
| XXL-Job | 2.4 | 定时任务：月卡到期提醒、日结、对账拉取 | 可选（可用 Spring Schedule 替代） |

> 起步可最小化：Redis 必须，RabbitMQ/MinIO/XXL-Job 可后置。首版若只做单场设备接入，可用 Spring Schedule + 本地磁盘存储过渡。

## 3. 数据库设计（新增表）

> 所有新表沿用一期通用字段约定：`id/create_time/update_time/deleted`；连锁表统一加 `lot_id BIGINT NOT NULL DEFAULT 0`（0=总部/默认）。

### 3.1 连锁相关（4 张）

```sql
-- 停车场（场）
CREATE TABLE parking_lot (
    id          BIGINT      NOT NULL AUTO_INCREMENT,
    lot_no      VARCHAR(30) NOT NULL COMMENT '场编号，如 LOT001',
    name        VARCHAR(50) NOT NULL COMMENT '场名称',

    deleted     TINYINT     NOT NULL DEFAULT 0,

-- 出入口（绑定相机/道闸）

    deleted    TINYINT     NOT NULL DEFAULT 0,

- 月卡/黑名单 `scope=1`（全集团）时不做场过滤。

## 4. 设备接入协议设计

### 4.1 相机 → 后端（识别上报）

```
POST /api/device/recognition     （设备鉴权：Header X-Device-Key: <api_key>）
{
  "deviceNo": "CAM-001",
  "gateId": 1,
  "plateNo": "京A12345",        // 可空
  "imageUrl": "http://.../xxx.jpg",
  "confidence": 0.98,
  "direction": 0,                // 0=入口 1=出口
  "captureTime": "2026-08-18 10:00:00"
}
响应：
{ "code": 0, "data": { "action": "OPEN_GATE" | "BLOCK" | "MANUAL", "message": "..." } }
```

- 后端收到后写入 `device_recognition`，按 `direction + plateNo` 走业务校验（黑名单/月卡/费用），返回动作指令；
- 幂等：以 `deviceNo + captureTime + plateNo` 为唯一键，Redis 布隆/唯一约束防重复开闸。

### 4.2 后端 → 道闸（开闸指令）

```
POST /api/device/{{deviceNo}}/gate
{ "action": "OPEN", "recordId": 123, "trigger": "AUTO" }
响应：{ "code": 0, "data": { "success": true } }
```

- 道闸控制通过 HTTP API 调设备厂家接口；失败自动重试 3 次 + 记录 `gate_log`；
- 开闸与停车记录在同一事务内失败时，执行「补偿」：若记录已建而闸未开，标记异常并推送人工处理。

### 4.3 设备鉴权

- 每个设备下发唯一 `api_key`（存 `parking_device`），请求头携带；
- 时间戳 + 签名防重放：`sign = MD5(deviceNo + timestamp + apiKey)`，5 分钟内有效；
- 独立过滤器 `DeviceAuthFilter`，不走用户 JWT 体系，与 `/api/auth/**` 分离。

### 4.4 模拟器（联调用）

- 开发期提供 `device-simulator` 脚本（Node/Python），读取视频帧/图片模拟相机识别上报，配置随机识别率，用于无真机联调。

## 5. 微信小程序方案

| 项 | 方案 |
| ---- | ---- |
| 框架 | uni-app（Vue3 语法，可同时编译微信/支付宝） |
| 登录 | `wx.login` → code2session 换 openid → 后端签发小程序专用 JWT |
| 手机号 | `getPhoneNumber` 获取手机号（需企业认证） |
| 支付 | 微信支付 V3（JSAPI），统一下单 → 预支付 → 支付回调（验签+幂等） |
| 月卡 | 复用一期 `membership_package`，小程序下单生成 `billing_order`（`pay_type=5 小程序支付`） |
| 查费 | 按车牌查在场记录 + 试算费用（复用一期计费引擎 `BillingService`） |
| 通知 | 订阅消息 `subscribeMessage`（入场/缴费/月卡到期模板） |

### 5.1 支付回调幂等设计

```
微信回调 → 验签 → 查本地订单(幂等判断)
  ├─ 已支付：直接返回成功，不重复处理
  └─ 未支付：标记已支付 → 若为出场订单 → 触发开闸指令 → 更新 parking_record 状态
```

- 本地订单增加 `payment_no`（微信支付单号）+ `pay_status` 字段；
- 回调处理加 Redis 分布式锁（`lock:pay:${orderNo}`），防止并发重复。

## 6. 实时推送（WebSocket）

- 管理端：设备离线/上线、识别异常、收费异常 → 顶部实时告警；
- 出场缴费：小程序支付成功后通过 WebSocket 通知现场收费员大屏「已缴费车牌」放行；
- 技术：Spring `WebSocketHandler` + STOMP，Nginx 需支持 `ws://` 升级（`proxy_set_header Upgrade`）。

## 7. 连锁化实施要点

1. **先改造数据层**：全部业务表加 `lot_id` + 迁移脚本，默认 `0`（=总部/默认场）；
2. **再改服务层**：`LotDataScopeInterceptor` 统一注入过滤条件，Service 层无感知；
3. **同步权限**：新增角色 `LOT_MANAGER`，前端菜单按角色 + `lot_id` 过滤；
4. **集团报表**：`report` 模块增加 `lotId` 维度，SQL 按场 GROUP BY 汇总。

  SPRING_DATA_REDIS_HOST / SPRING_MINIO_URL / SPRING_RABBITMQ_HOST
```

### 9.2 后期（多场规模化）

- 后端拆「网关 + 业务服务」或继续单体但水平扩容（无状态化，会话入 Redis）；
- 数据库主从：主库写、从库读（报表查询走从库）；
- 对象存储统一 MinIO 集群 / 云厂商 S3；
- 引入注册中心（Nacos）+ 配置中心，支撑多场动态配置下发。

## 10. 开发任务拆分建议（与需求文档里程碑对应）

## 11. 质量与上线

- 测试：设备模拟器联调用例（识别失败/重复上报/断网重传）、支付回调幂等用例、并发开闸用例；
- 安全评审：设备 API 签名、支付验签、HTTPS 强制、敏感字段脱敏；
- 灰度：先单场试运行 2 周（人工+自动并行），数据核对无误后全量切换；
- 回滚预案：保留人工出场兜底路径，设备故障时一键切换「纯人工模式」。
